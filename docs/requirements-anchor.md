## 1. 背景与核心问题

### 1.1 业务背景

外置功放（External Amplifier）的微型 HIL 测试项目，一次测试所需的前置资料分散在多处：一张 Excel 需求分析表（需求 + 各车型差异变体）、一组按项目配置参数维护的车型取值、一份 `车型=slot 路径` 的通道映射、一个描述场景/步骤/出声扬声器的出声位置文件、一张车型 × 音源 × 音量档位的音量表、一个存放通道与扬声器对应关系的快照目录，以及 Gauge 项目自身的 `.spec` 规格与 `.cpt` 步骤封装。

这些资料的维护者、格式与更新节奏都不相同，但彼此存在强关联：**spec 场景上的车型标签，本质上是若干"配置项-配置值"生效车型的集合运算结果。**

### 1.2 当前痛点

| 痛点                       | 具体表现                                                                              |
| -------------------------- | ------------------------------------------------------------------------------------- |
| 手工整理 Excel             | 需求与车型差异只存在于表格里，无法被程序引用；每次核对靠人工比列                    |
| 跨文件查找                 | 一次开测要在 Excel、INI 映射、出声位置文本、音量表、快照目录之间反复跳转             |
| 场景标签人工维护           | spec 场景的车型标签由人手工写、手工改，配置参数一变就可能与标签漂移                   |
| 多项目数据混用风险         | 同一批资料服务多个车型/项目，缺省按目录复制，容易出现"看着是 A 项目的数据"            |
| 资料异常不可见             | 引用失效、文件缺失、条件写错时，工具无感知，错标会被当成正确结果提交                  |

### 1.3 核心问题陈述

**把"配置参数 → 生效车型 → spec 场景标签"这条链从人脑里搬到工具里，并让每一个引用断裂、文件缺失和语法错误都在写回之前显式暴露。**

这是当前版本唯一成立的核心价值主张；它成立的前提是资料本身仍由外部维护，工具只做结构化的读、算、写。任何超出该链的需求（例如开测执行、硬件控制）都属于另一个立项（见第 4 节非目标）。

以下前提当前**不具备**，不得在验收中被默认：硬件连接与设备控制、测试执行与结果判定、实时播放与电平采集、业务资料的在线编辑。

## 3. 产品愿景（一句话）

> **一个以 Gauge 项目为数据边界的本地桌面工具台，把外置功放 HIL 测试的需求、配置、资料与 spec 车型标签收敛到同一个应用里，并让配置参数成为车型标签的唯一可计算来源。**

## 4. 范围边界

### 4.1 本次要做的功能大类（5 个模块级需求）

| 编号 | 模块                                     | 范围要点                                                                                     | 优先级 |
| ---- | ---------------------------------------- | -------------------------------------------------------------------------------------------- | ------ |
| M1   | 项目工作区与数据边界                     | 绑定 Gauge 项目（`manifest.json` / `.gauge`）、最近 5 项、失效路径过滤、切换即重载、按项目的 `settings.json` | P0     |
| M2   | 需求与配置参数的结构化维护               | Excel 导入（探测→预览→保存）、变体归一合并、配置项/配置值 CRUD、变体引用、手工车型、失效与歧义引用显式提示 | P0     |
| M3   | 四类业务资料只读查看器                   | SLOT 映射（含 slot 文件）、出声位置、音量表、扬声器快照；区分未配置/缺失/读取失败/无结果      | P1     |
| M4   | spec 条件求值与标签写回                  | 集合布尔运算（`&`/`&&`、`|`/`||`、`!`/`~`、括号）、未知引用与语法错误安全失败为空集、预览后幂等写回 | P0     |
| M5   | Gauge 封装结构化维护                     | 递归列出 `.cpt`、保存前格式校验、增/改/删（含删最后一条即删文件）、路径限制在 `concepts` 内  | P1     |

M1 的落地形态包含项目设置弹窗（数据路径 + 导入默认参数），它是 M2～M5 的路径来源，故不单列。

### 4.2 明确不做的内容（非目标）

1. **不做 HIL 硬件能力**：不接串口、总线、采集设备或功放设备，不做设备发现、参数下发与状态读取。
2. **不做测试执行**：不调度 Gauge runner、不启停测试、不采集实时音频或电平、不做测试结果判定与报告。
3. **不做业务资料在线编辑**：SLOT 映射、出声位置、音量表、快照四类文件保持只读；工具不提供写接口。
4. **不做"新建任务"功能**：仅保留导航入口与占位页；任务模型、执行方式与结果定义不在本期（见 Q2）。
5. **不做多用户体系**：无账号、权限、云同步、服务端数据库与协同编辑。
6. **不做移动端/平板/纯 Web 生产部署**：桌面端专属，不写响应式断点。
7. **不做数据安全网**：无自动备份、撤销、版本历史、跨文件事务、外部并发修改检测。
8. **不做发布工程**：无安装包制作、签名、自动更新与发布渠道（当前 `package.json` 未定义）。
9. **不做性能承诺**：在性能基线签署前，不把启动耗时、导入耗时、最大车型数当作已验收指标。

> 事实备注：当前会话环境里存在可用的串口 MCP 工具，但仓库代码中没有任何串口/总线接入实现，不能据此认为项目已具备 HIL 硬件能力。

## 6. 关键约束与依赖

### 6.1 技术栈（已锁定）

| 类别   | 现状                                                                                          |
| ------ | --------------------------------------------------------------------------------------------- |
| 前端   | Vue 3.5 + TypeScript 6 + Vite 8 + Pinia 4 + Vue Router 5                                      |
| UI     | Element Plus 2（按需自动导入）、Tailwind CSS 4（CSS-first `@theme`）                          |
| 桌面壳 | Electron 45，`contextIsolation: true` / `nodeIntegration: false` / `sandbox: true`            |
| Excel  | SheetJS 0.18；必须"Node 读字节 + `XLSX.read(buffer)`"，ESM 下 `readFile` 不可用                |
| 运行时 | Node `^22.18.0` 或 `>=24.12.0`                                                                |
| 测试   | Vitest（14 文件 / 133 条）、`vue-tsc` 类型检查、oxlint + ESLint                               |

### 6.2 架构约束（不可绕过）

- 渲染进程不直接触达文件系统，一切 Node 能力经 preload 白名单 IPC（`window.desktop`）。
- 主进程输出 ESM，preload 在 `sandbox: true` 下必须为 CommonJS（`dist-electron/preload.cjs`）。
- 解析与条件求值保持为纯函数，可脱离窗口单测；跨进程共享类型只用 `import type` 与相对路径。
- 数据契约有版本：`requirements.json` / `config.json` / `settings.json` 的 `schemaVersion = 1`，读取方拒绝不支持的结构。
- 界面约束：12 列栅格（外壳三栏 `3·5·4` 为唯一例外）、无边框自绘标题栏、DIP 布局且不设 `zoomFactor`、`html.dark` 单一主题开关、桌面端不写断点。

### 6.3 外部依赖

| 依赖                   | 形态                                       | 谁维护     | 失效后果                             |
| ---------------------- | ------------------------------------------ | ---------- | ------------------------------------ |
| Gauge 项目目录         | `manifest.json` 或 `.gauge` 标记            | 外部       | 无法绑定项目，应用停在启动页         |
| 需求分析表             | `.xlsx` / `.xlsm` / `.xls`                 | 外部       | 需求与所有派生车型为空               |
| `specs/**/*.spec`      | Gauge 规格 + `适用条件:` 扩展               | 工具可写标签 | 标签漂移                             |
| `concepts/**/*.cpt`    | Gauge 封装                                 | 工具可写   | 封装不可复用                         |
| SLOT 映射 + slot 文件  | `车型=路径` 文本 + 被引用文件              | 外部只读   | 通道对应关系不可查                   |
| 出声位置 / 音量表 / 快照 | 自定义文本 / UTF-8 分隔文本 / txt 目录    | 外部只读   | 对应页面为空态或警告                 |

### 6.4 已知约束与风险（来自规格书第 15 章）

- **R-01 功能不一致**（`electron/settings.ts:28-31` 的 `PICK_FILTERS['volume-table']` 与 `business-store.ts` 的 `readVolumeTable`）：音量表选择器允许 `.csv/.xlsx/.xls`，解析实现只支持 UTF-8 文本，选到 Excel 会得到错行而不是报错 —— 二选一必须现在定。
- **R-02 无跨文件事务**：spec 多文件写回中途失败会留下部分新标签，且不回滚。
- **R-03 有损保存**：`.cpt` 结构化保存会丢概念内注释与原始排版；表格 `|---|` 分隔行不保留。
- **R-04 并发**：外部程序或另一个 AI 会话同时改同一文件时，后写覆盖先写；当前假设是"所有者 + 单一会话编辑"，但 2026-11-07 已实测两次同工作区提交撞车。
- **R-05 测试缺口**：窗口、IPC、主要页面、E2E 无自动化覆盖，133 条不代表已验收。
- **R-06 性能无基线**：见 S6 / Q4。
- **R-08 路径安全**：spec/cpt 已是 `resolve` + `startsWith(base + sep)` 前缀校验（`electron/specs.ts:32-33`、`concepts.ts:33-34`），能挡住目录外绝对路径与 `../` 逃逸；但未做 `realpath`，符号链接与 Windows 重解析点仍可绕过。

### 6.5 合规与组织约束

数据脱敏要求、审计留痕要求、交付时间与人力投入 —— 均为【待确认】，见 Q5。
