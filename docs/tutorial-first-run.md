# 教程：完成首次多车型 HIL 运行

本教程按一次可验证的完整运行组织。完成后，你能够从 Gauge 项目资产出发，生成一个车型的需求映射、配置、目标 CPT、车型标签和 Gauge 运行结果。

## 前置条件

- 已安装 Node.js、Electron 依赖和 Gauge CLI。
- 有一个 Gauge 项目根目录，目录包含 `manifest.json` 或 `.gauge`。
- 项目中已有需求分析表、SLOT 映射、出声位置和 `specs` 目录。

启动：

```sh
npm install
npm run dev
```

在启动页选择 Gauge 项目根目录。应用进入主界面后，先打开标题栏「项目设置」。

## 步骤 1：配置项目资产路径

在项目设置中配置路径。相对路径统一写成 `./...`：

| 设置项 | 示例 | 用途 |
| --- | --- | --- |
| 需求分析表 | `./config/关联需求/需求分析表.xlsx` | 运行前自动导入需求 |
| 需求数据 | `./.hil-kit/requirements.json` | 需求、变体和映射参与状态 |
| 配置参数 | `./config/配置参数/config.json` | 配置项、配置值、变体引用 |
| 出声位置文件 | `./config/出声位置/出声位置.txt` | 出声场景和扬声器关键字 |
| SLOT 映射目录 | `./config/SLOT映射` | 每个 `.txt` 为一种映射方案 |
| 扬声器快照文件 | `./config/扬声器快照/snapshot.ini` | 快照分节和通道扬声器 |
| 音量表文件 | `./config/音量表/test.csv` | 车型 × 音源 × 音量 |
| 出声位置目标CPT文件 | `./specs/concepts/出声位置.cpt` | 运行前替换出声位置实现 |
| SLOT映射目标CPT文件 | `./specs/concepts/SLOT映射.cpt` | 运行前替换 SLOT 实现 |
| Gauge 可执行文件 | `gauge.exe` 或留空 | 留空使用 PATH 中的 Gauge |
| 环境名 | `default` | 写入 `env/<环境>/value.properties` |
| 附加参数 | `--verbose` | 插入 `gauge run` 与规格书路径之间 |

保存后关闭设置弹窗。每次页面切换都会重新读取这些本地持久化数据。

## 步骤 2：导入软件需求

打开「软件需求」，点击「导入 Excel」：

1. 选择需求分析表。
2. 核对工作表、表头行和列映射。
3. 点击「预览」，确认需求、变体和车型数量。
4. 点击「导入」。

导入结果写入 `requirements.json`。需求 ID 和名称会去掉所有空白字符，车型名会归一化为「无空白、`-` 改 `_`」。

在需求表的「映射」列中：

- 选择「参与」：该需求参与参数映射。
- 选择「不参与」：该需求不参与参数映射，状态固定为正常。

该状态写入 `requirements.json` 的 `mapping` 字段。

## 步骤 3：维护配置参数

打开「配置参数」，新建配置项和配置值。配置值可以通过两种方式得到适用车型：

1. 关联需求变体；
2. 填写特殊车型规则：
   - 车型名称以 `xxx` 开头；
   - 车型名称包含 `xxx`。

检查三层状态：

| 层级 | 正常 | 浮空 | 异常 / 失效 |
| --- | --- | --- | --- |
| 关联变体 | 找到对应变体 | 不适用 | 失效 |
| 配置值 | 全部变体正常，或无关联但有特殊车型配置 | 无关联且无特殊车型配置 | 存在失效引用 |
| 配置项 | 所有配置值正常 | 存在浮空配置值或无配置值 | 存在异常配置值 |

## 步骤 4：准备 Gauge 资产

### 出声位置

在 `出声位置.txt` 中维护场景和关键字：

```markdown
# 检查智能语音全车播放时出声位置是否正确
适用车型:SC6H/YU2
* step1
* speak="左前低音|左前高音|中置"
* no_speak="右前低音|右后低音"
```

规则：

- 未写 `适用车型` 表示全部车型。
- 只识别步骤中的 `speak=` 和 `no_speak=`。
- 关键字用 `|` 分隔。
- 旧式 `* 左前低音|左前高音` 只会作为普通步骤保留。

### SLOT 映射

`config/SLOT映射/*.txt` 中：

```markdown
适用车型:SC6H/YU2
# 音源盒打开媒体音SLOT
* 音源盒打开SLOT1
* 音源盒打开SLOT2
```

规则：

- 首行 `适用车型:` 写车型，多个车型用 `/` 或逗号分隔。
- `#` 是音源场景。
- 步骤中的 `SLOT数字` 是通道。
- `sleep` 等无 SLOT 步骤会显示为 `-`。

### 规格书

在 `specs/**/*.spec` 中写 `适用条件`：

```markdown
适用条件:媒体音源默认值-0x0无音源

## 一个场景
适用条件:示例参数-示例配置值1
```

条件引用 `配置项-配置值`。支持 `&`、`|`、`!`、括号，以及空条件和保留字。

## 步骤 5：选择运行车型并执行

打开「新建任务」：

1. 在左侧规格树勾选要运行的场景。
2. 选择运行车型，例如 `SC6H`。
3. 点击「一键配置运行」。

如果要保存任务，先填写任务名称并点击「保存」，再点击「运行任务」。

执行顺序：

1. 导入最新需求。
2. 刷新配置并检查异常配置。
3. 更新场景车型 `tags`。
4. 重建出声位置目标 CPT。
5. 重建 SLOT 映射目标 CPT。
6. 更新 `env/<环境>/value.properties` 中的 `vehicle_model`。
7. 执行 `gauge --tags <车型>`。

也可以从「规格书」或「测试队列」执行。测试队列会在每个队列项执行前，按该项记录的车型重复上述配置。

## 步骤 6：验证结果

底部终端应显示配置步骤和 Gauge 输出。例如：

```text
需求导入：20 条需求 / 48 个变体
配置参数：已刷新
车型 tags：更新 3 个 spec 文件
出声位置目标 CPT：./specs/concepts/出声位置.cpt
SLOT 映射目标 CPT：./specs/concepts/SLOT映射.cpt
$ "gauge" "run" "specs/example.spec" "--tags" "SC6H"
退出码：0
```

同时检查：

- `env/<环境>/value.properties` 中的 `vehicle_model` 是否等于所选车型。
- 目标 CPT 是否按车型替换完成。
- Gauge 报告中是否只执行了该车型适用的场景。

## 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 选择项目失败 | 目录不是 Gauge 项目 | 选择包含 `manifest.json` 或 `.gauge` 的目录 |
| 需求导入失败 | Excel 路径、工作表或列映射错误 | 重新打开导入弹窗并预览 |
| 配置异常阻断运行 | 失效引用、异常配置值 | 到配置参数页修复引用 |
| 条件解析告警 | 适用条件引用不存在 | 检查 `配置项-配置值` 写法 |
| 目标 CPT 生成失败 | 概念格式错误或路径错误 | 检查目标 CPT 和概念格式 |
| Gauge 启动失败 | 可执行文件或附加参数错误 | 检查 Gauge 运行设置 |
| `vehicle_model` 未更新 | 环境名或权限错误 | 检查 `env/<环境>/value.properties` 写权限 |
| 没有运行车型 | 未选择车型 | 在运行入口选择运行车型 |
