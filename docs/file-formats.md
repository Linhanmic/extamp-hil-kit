# 项目文件格式定义

本文把所有由本项目读写的文件格式集中定义在一处：文件落在哪、谁写、字段与语法约束、边界情况怎么处理。功能级验收条件见 [项目规格书](project-specification.md)，单格式的详细说明见对应的专项文档（`requirements-json.md` / `config-json.md` / `settings-json.md`）。本文与代码冲突时以代码为准，并回写修订本文。

## 1. 总览

| --- | --- | --- | --- |

| `config.json` | `<项目>/.hil-kit/`（可由设置改到别处） | 配置参数页（整份写回） | [config-json.md](config-json.md) |

## 2. 通用约定

- **编码**：所有文本文件按 UTF-8 读写，不带 BOM；读入时容忍 BOM（`\uFEFF` 会被去掉）。
- **行尾**：写回时新建文件用 `LF`；修改既有文件时沿用该文件原有的行尾风格（读到的 `\r\n` 保持 `\r\n`）。
- **行号 / 列号一律 1 基**：Excel 表头行、解析告警行号都按 Excel 行号（第 1 行是 1），列位置用 Excel 列字母（`A`、`AE`）或 1 基列号。界面上输入的表头行号与探测结果都是同一个口径，不出现 0 基行号；`0` 只在设置里表示「自动探测」。
- **车型名归一化**：删除所有空白字符，再把破折号 `-` 换成下划线 `_`。多车型字符串按 `/`、`、`、`,`、`，`、`;`、`；` 拆分后逐个归一化。归一化后的名字用于配置关联、SLOT / CPT 生成和 `gauge --tags`。
- **变体内容键**：变体描述经 NFKC 归一后，只删除控制字符与空白字符；破折号（`—`）、实心点（`●`）等标点与符号原样保留。原始写法另存于 `content`，不因合并而丢失。
- **时间**：JSON 里的时间字段为 ISO 8601 UTC 字符串；`createdAt` 首次写入后不再变，`updatedAt` 每次写回刷新。
- **结构校验**：读取方拒绝结构不符或 `schemaVersion` 不受支持的文件，并在界面提示，不展示半份数据。
- **路径**：设置里的路径可为相对（按项目根解析）或绝对；写回前统一做目录前缀校验，越界路径被拒绝。

## 3. 结构化数据文件（JSON）

字段级定义见专项文档，这里只固定共同约定：顶层固定 `schemaVersion`（当前均为 `1`）、`createdAt` / `updatedAt`、业务数组；不落盘的数据（列配置、车型全集、统计告警、派生车型）一律不入库。

## 4. 需求 Excel（导入源，不在项目里写回）

- 支持 `.xlsx` / `.xlsm` / `.xls`；用 Node 读字节后交给 SheetJS（`XLSX.read(buffer)`）。
- 表头行按 1 基行号指定；列位置按 Excel 列字母指定。空串 / `0` 表示自动探测。
- 单元格语义：`●` 适用且无变体差异；`●` 之后的全部文本是变体描述（换行、空格、标点、实心点、破折号原样保留）；`—` 不适用；空表示未填写。
- 表头含「平台」的列整列忽略，不进车型清单；单个空表头跳过，连续两个空表头停止向右扫描。

## 5. 出声位置文件

```text
# 检查智能语音关闭时出声位置是否正确
* step1
* no_speak="左前低音|左前高音|中置"

# 检查智能语音全车播放时出声位置是否正确
适用车型:SC6H/YU2
* step1
* speak="左前低音|中置"
```

- `# ` 开头的行开启一个场景，其后文本是场景标题（生成 CPT 时直接当封装标题，不改写）。
- `适用车型:` / `适用车型：` 行声明该场景的适用车型，多车型用 `/` 等分隔；**不写**表示全部车型（默认项）。
- `* ` 开头是步骤行；`speak="…"` / `no_speak="…"` 写在步骤行内，引号内多个关键字按 `|` 分隔，读取侧从步骤里提取关键字，未带指令的步骤按普通步骤保留。
- 其他非空行按普通步骤保留。
- 场景之间用一个空行分隔；整份文件是「场景列表」的唯一载体，增删改都通过整份写回完成。
- 写回规则：按 `# 标题` → 可选 `适用车型:` → 各 `* 步骤` 输出，标题与步骤原样照抄（除首尾空白）。

## 6. SLOT 映射文件

一个目录下每个 `*.txt` 是一种映射方案，文件名（去掉后缀）就是方案名。

```text
适用车型:SC6H/YU2/SF海外

# 音源盒打开媒体音SLOT
* 音源盒打开SLOT1
* 音源盒打开SLOT2

# 音源盒打开电话音SLOT
* 音源盒打开SLOT13
```

- `适用车型:` 行在方案级（不是场景级），可以不写——不写表示不限车型，作默认方案。
- `# ` 开头是音源场景标题；`* ` 开头是步骤，步骤里的 `SLOT数字` 被提取为该场景的通道号；不带 `SLOT` 的步骤（如 `sleep "100ms"`）记为非 SLOT 步骤，通道列显示 `-`。
- 写回：整份文件按上例生成；文件名必须是纯文件名（不含路径分隔符）且以 `.txt` 结尾；删除即删该文件。

## 7. 音量表文件

- UTF-8 分隔文本，分隔符从 `;` / `,` / Tab 中按首行出现次数自动识别，写回沿用原分隔符。
- 首行是表头，必须能定位「车型」「音源」列，其余列是音量档位（0–39）。
- 数据行：车型（多车型用 `/`）、音源类型、各档位 dB 值（可留空）。
- 不支持内嵌分隔符或换行的单元格，也不支持 Excel 二进制；这类输入在保存前被拒绝。

## 8. 扬声器快照 `snapshot.ini`

```ini
[SC6H]
左前低音
左前高音

[SC6H/YU2]
中置
重低音
```

- `[适用车型]` 是分节名，多车型用 `/` 分隔；分节名与车型列表一一对应。
- 分节内每行一个扬声器，行序即通道号（第 1 行是通道 1）；兼容 `通道N对应扬声器` 写法，读取时去掉该前缀。
- 写回：按分节顺序输出，分节之间空一行；分节名不允许包含 `[`、`]` 或换行。

## 9. spec 的场景标签与适用条件

- Gauge 原生语法不变；本项目额外识别 `适用条件:` 指令行。首个 `##` 场景之前写的条件作用于整份规格书，之后写的作用于该场景。
- 场景最终车型 = 规格书条件 ∩ 场景条件；条件表达式支持 `&` / `&&`（交）、`|` / `||`（并）、`!` / `~`（补）、括号。
- 标签写回**整行重写**：原有 `tags:` 行（含 `manual` 这类手工标签）全部清除，只写算出的车型集合；无车型适用时写 `不适用`。`适用条件:` 行与正文不受影响，多行标签合并为一行，行尾风格保持。

## 10. 封装文件 `.cpt`

- 单 `#` 为封装标题（标题内只能用 `<参数名>` 动态参数，禁止 `"静态值"` 与 `:特殊参数`）；`*` 为步骤；`|a|b|` 是挂在上一步骤下的内联表格；禁止 `##` 场景标题。
- 结构化保存会重新生成整个文件：概念内注释与原始排版不保留，表格不写 `|---|` 分隔行。

## 11. 目标 CPT（按车型生成）

目标 CPT 是**一份文件**，由「默认项 + 车型差异项」合并而成，spec 侧用统一概念名引用，切换车型靠替换实现。

- **默认项**：源数据里不带适用车型的场景（出声位置 `allVehicles`、SLOT 映射不限车型的方案）。
- **车型差异项**：适用车型命中当前车型的场景。
- **合并规则**：
  1. 先落默认项；
  2. 车型差异项与默认项**同名标题**时，就地替换默认项（默认项位置不变，内容换成车型版本）；
  3. 默认里没有的标题追加到末尾；
  4. 同类内部标题重复时后者覆盖前者，并在生成结果提示里给出「同名覆盖」数量。
- **内容不改写**：封装标题就是源文件里的场景标题，不在前面拼车型名或方案名；步骤原样照抄。合并后标题天然唯一，可直接过 `validateConcepts` 校验。
- **写回**：合并结果序列化成 `.cpt` 文本（`# 标题` + `* 步骤`），整份写入设置里的目标文件；SLOT 目标 CPT 用独立的目标设置。

示例（源文件里有同名场景的两个版本）：

```text
# 默认（不留适用车型）
# 媒体音源播放时检查出声位置是否正确
* speak="左前高音|中置"

# 车型差异（适用车型:SC6H）
# 媒体音源播放时检查出声位置是否正确
* speak="左前高音"
```

生成到 SC6H 时，目标 CPT 只有一条同名封装，内容是 SC6H 的版本；车型差异里没有的默认项原样保留。
